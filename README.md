# 질의답변수 집계표 — GitHub Pages 버전

이 폴더를 그대로 GitHub 저장소로 올리면 웹사이트가 됩니다.

```
index.html          집계표 화면
로그데이터/          여기에 로그 xlsx 를 넣습니다
  ├─ manifest.json   ← 파일 목록 (목록갱신.bat 이 만들어 줍니다)
  └─ (로그 파일들)
목록갱신.bat         manifest.json 다시 만들기 (이걸 더블클릭)
update_manifest.ps1  실제 로직 — 배치가 호출합니다
```

---

## ⚠️ 올리기 전에 반드시 확인

**1. 데이터가 공개됩니다.**
로그에는 질문·응답 본문은 없지만 **채널명 · AI 모델 · 접속 시각 · 식별번호**가 들어 있고,
채널명에는 과목명·기관명이 포함됩니다. 식별번호는 개인 식별에 쓰일 수 있습니다.
**Public 저장소면 전부 인터넷에 공개되므로 Private 저장소를 쓰세요.**

**2. 방문자가 매번 데이터 전체를 내려받습니다.**
40MB 파일을 올리면 페이지를 열 때마다 40MB를 받고 변환에 20초쯤 걸립니다.
**월별로 잘게 나눠** 올리는 편이 낫고, 필요한 기간만 폴더에 두는 것도 방법입니다.

**3. 웹 업로드는 25MB 제한입니다.**
GitHub 웹사이트 드래그 업로드는 파일당 25MB까지입니다. 그보다 크면 `git push` 를 쓰세요
(파일당 100MB까지).

## 쓰는 순서

### 1) 로그 파일 넣기

`로그데이터/` 폴더에 xlsx(또는 csv)를 넣습니다. 개수 제한 없고 파일명은 자유입니다.

필요한 컬럼 — 순서 무관, 다른 컬럼이 더 있어도 무시합니다.

| Chat ID | 채널 ID | 채널명 | 생성일시 | AI 모델 | 식별번호 *(선택)* |
|---|---|---|---|---|---|

`식별번호` 가 있으면 이용자 수를 정확히 계산합니다. 없으면 고유 채널 ID 수로 대체하고
화면에 그 사실을 표시합니다.

> 중복 제거를 하지 않습니다. 같은 기간이 든 파일을 두 개 넣으면 건수가 두 배가 됩니다.
> 겹치면 화면 상단에 **빨간 경고**가 뜨니 확인하세요.

### 2) (공개 저장소면 생략 가능)

페이지가 파일 목록을 찾는 순서는 이렇습니다.

| 순서 | 방법 | 쓰이는 곳 |
|---|---|---|
| 1 | 폴더 목록 HTML | 로컬 `열기.bat` (python 서버) |
| 2 | **GitHub API** | **github.io + 공개 저장소 — 자동, 갱신 불필요** |
| 3 | `manifest.json` | 비공개 저장소 · 다른 호스팅 |

**공개 저장소라면 아무것도 안 해도 됩니다.** 파일을 올리면 GitHub API 로 목록을 바로 읽습니다.

비공개 저장소이거나 GitHub API 호출 한도(시간당 60회)를 넘겼을 때만
`목록갱신.bat` 을 실행해 `manifest.json` 을 만들어 두세요.

### 3) 올리기

```bash
git init
git add index.html 로그데이터 README.md
git commit -m "집계표 사이트"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

**Settings → Pages → Source: Deploy from a branch → main / (root)** 로 설정하면
`https://<계정>.github.io/<저장소>/` 에서 열립니다.

데이터를 갱신할 때는 파일 교체 → `목록갱신.bat` → `git add . && git commit && git push`.

## 로컬 버전과 다른 점

| | 로컬 (`web/`) | GitHub (`github_사이트/`) |
|---|---|---|
| 실행 | `열기.bat` (python 로컬 서버) | 웹 주소로 접속 |
| 파일 목록 | 폴더를 자동으로 훑음 | `manifest.json` 필요 |
| 목록 갱신 | 불필요 | `목록갱신.bat` 실행 |
| index.html | 동일 | 동일 |

`index.html` 은 두 방식을 모두 지원합니다. `manifest.json` 이 있으면 그걸 쓰고,
없으면 폴더 목록을 훑습니다. 그래서 이 폴더는 로컬에서도 그대로 테스트할 수 있습니다.

```bash
python -m http.server 8000
```

## 파일을 못 찾는다고 나올 때

화면에 `같은 폴더에서 로그데이터.xlsx ... 을 찾지 못했습니다` 가 뜨면
**`manifest.json` 이 비어 있거나 없는 것**입니다. 아래 순서로 확인하세요.

1. `로그데이터/` 폴더에 xlsx 파일이 실제로 있는지
2. **`목록갱신.bat` 을 실행**했는지 → `로그데이터/manifest.json` 을 열어
   파일명이 적혀 있어야 합니다
   ```json
   { "files": [ "expansion_logs_2025-12-01_....xlsx" ] }
   ```
3. `manifest.json` 과 로그 파일을 **둘 다** git 으로 올렸는지
4. 브라우저에서 `https://<주소>/로그데이터/manifest.json` 을 직접 열어
   내용이 보이는지 (404 면 업로드가 안 된 것)

`목록갱신.bat` 과 `update_manifest.ps1` 은 로컬 전용 도구이며 GitHub 에 올리지 않아도 됩니다.

> **왜 파일이 두 개인가** — Windows 명령 프롬프트는 배치 파일을 CP949 로 읽어서,
> 배치 안에 한글이 있으면 명령이 깨집니다(`powershell` 이 `hell` 로 잘리는 식).
> 그래서 배치는 ASCII 로만 두고 한글 처리는 `.ps1`(UTF-8 BOM)에 맡겼습니다.
> **두 파일은 같은 폴더에 함께 있어야 합니다.**
